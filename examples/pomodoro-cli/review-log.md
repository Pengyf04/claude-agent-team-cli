# Review Log：pomodoro-cli

## 第 1 轮评审

**总评**：方案结构清晰，函数契约化、AC 量化区间、关键取舍有论证，正确性/完整性/最优性三个维度均成立（7 条 task 标准全覆盖、无过度设计、计数语义自洽）。但存在 3 处会直接导致验证误判或执行歧义的具体缺陷，必须修正后放行。

### 必改项

- [可验收性] **AC4 判定词与实现文案不一致**：AC4 要求输出含「已完成」，但 2.2 中断文案为「已中断，本次共完成 X 个完整周期。」——其中不含连续子串「已完成」（只有「已中断」「共完成」），verifier 照 AC 判定必然假 FAIL。→ 二选一统一：把中断文案改为「已中断，已完成 X 个完整周期。」，或把 AC4 判定词改为「共完成」+「个完整周期」。
- [可验收性] **AC2 正则未转义**：`[工作] 周期 \d/\d 剩余 \d{2,}:\d{2}` 中 `[工作]` 在正则里是字符类（匹配单字符「工」或「作」），对实际输出 `[工作] 周期 1/2 …` 匹配数为 0，verifier 照抄即假 FAIL。→ 改为 `\[工作\] 周期 \d/\d 剩余 \d{2,}:\d{2}`，或在 AC2 注明「按字面子串匹配，非正则」。
- [可执行性] **2.2 main 伪代码自相矛盾**：main 的 `except KeyboardInterrupt` 分支引用了 main 作用域不存在的 `completed`（照抄即 NameError），同一段又写「推荐把 try/except 放进 run」，两个方案并存留给执行者两可。→ 删除 main 中的 except 伪代码，明确唯一实现：run 内部 try/except KeyboardInterrupt 并打印计数，main 只做 `parse_args + run + return 0`。

### 建议项（非阻塞，采纳与否不影响放行）

- [可验收性] AC4 的 SIGINT 时刻定在 4 秒，紧贴 completed=0→1 转变点（约 t≈3.1~3.3，含启动开销）且恰落在休息1→工作2 边界；机器负载稍高即可能 completed=0 误判。建议改为 **5 秒**（工作2 中段，双侧余量 ≥2 秒），期望值仍为「1 个完整周期」。
- [可验收性] AC5 判定「默认值 25、5、4 的字样」：ArgumentDefaultsHelpFormatter 对 float 默认值实际显示 `25.0`/`5.0`，按子串可过；建议在 AC5 注明「25.0/5.0 亦符合」，防 verifier 用 `default: 25` 精确匹配误判。

### 已核对无问题的点（免重复争论）

- 「最后周期不休息」+「工作完成即计 1 周期」的组合使 Ctrl+C 计数语义唯一，认可。
- AC1 区间 6–14s 覆盖名义 7s+抖动；AC3 响铃 ≥4 次与 notify 调用次数（2+1+1）吻合。
- `--break` dest 重命名、minutes_to_seconds 最小 1 秒保底、pytest 非标准库的 R1 处置路径均正确。
- 测试用例设计（3 参数解析 + 2 时间格式化，无 sleep）满足 task#6。

判定：NEEDS_REVISION
